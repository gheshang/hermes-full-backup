# 长报告 → PPT 内容提取模式

## 适用场景

用户提供一份长篇报告/文档/文章，希望生成 PPT。原始文档通常在 1-5 万字，包含技术概念、市场数据、政策条文、案例研究等混合内容。

## 核心方法：三层并行提取

不要让单个 agent 一次性读完整个报告再写大纲——上下文窗口容易溢出，且不同类别的内容需要不同的提取思维。

用 `delegate_task` 启动 **3 个并行 leaf subagent**，各司其职：

| 子代理 | 任务 | 输入 | 输出格式 |
|--------|------|------|----------|
| **论点提取器** | 提取核心论述/金句 | 报告全文路径 | 每条 ≤40 字 bullet，标注来源章节 |
| **数据提取器** | 提取所有可量化数据 | 报告全文路径 | `数字 \| 含义 \| 来源`，一行一条 |
| **案例提取器** | 提取案例摘要 | 报告靶向章节 | `案例名 → 痛点 → 方案 → 效果`，每个 4 行 |

### 关键约束

1. **所有 3 个子代理同时启动**——它们之间无依赖，并行可节省 60% 总时长
2. **每个子代理给 `toolsets: ["file","terminal"]`**——只需读文件，不需要网络
3. **context 里给清文件绝对路径**——子代理没有当前会话的记忆
4. **明确输出格式**——让子代理知道要回什么结构，合并时不用二次整理

### 示例调用

```
delegate_task(tasks=[
  {goal: "提取核心论点...", context: "文件路径: /path/to/report.md\n受众: 企业全体员工\n输出格式: bullet + 来源章节", toolsets: ["file","terminal"]},
  {goal: "提取可量化数据...", context: "文件路径: /path/to/report.md\n输出格式: 数字|含义|来源", toolsets: ["file","terminal"]},
  {goal: "提取案例摘要...", context: "文件路径: /path/to/report.md\n目标: 第5章案例\n输出格式: 案例名→痛点→方案→效果", toolsets: ["file","terminal"]},
])
```

## 合并与大纲化

子代理返回后，人工/Agent 做一次合并：

1. **论点** → 控制叙事弧的节奏（钩子放 P01-P02，核心论点放 P03-P07，转折放 P13）
2. **数据** → 挑选 3-5 个"拳头数字"放大字报页，其余放正文注释
3. **案例** → 每个案例 1 页，左文右图或流水线布局，把"效果数据"放大

生成的 PPT 页数经验公式：**报告字数 / 2000 ≈ 页数**（3.2 万字 → 17 页，吻合）。

## Pitfalls

- **不要用一个 agent 读完整个报告**：3 万字以上的报告，单 agent 读完再整理，容易遗漏后半段内容或混淆章节归属
- **子代理的 context 要写明受众**：同一个报告给「全体员工」vs「行业专家」提取出来的论点完全不同
- **案例提取器要指定章节**：否则它会扫描全文浪费 token
- **数据提取器要指定"含单位"**：否则会漏掉"亿美元 vs 亿元"这种关键信息
