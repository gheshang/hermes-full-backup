# 企业级自动化管理系统 · 构建指南

## 核心定位

> **不是单个工具，而是一套架构**：多通道输入 → 混合分析 → 多通道输出 → 持续优化

## 架构设计

```
┌─────────────────────────────────────────────────────────────────┐
│                        信息接收层                                │
│  ┌──────────────┐              ┌──────────────┐                │
│  │  企业微信     │              │    飞书       │                │
│  │  Webhook     │              │  Webhook     │                │
│  └──────┬───────┘              └──────┬───────┘                │
│         └─────────────┬───────────────┘                         │
│                       ▼                                         │
│              ┌────────────────┐                                 │
│              │  统一接入服务   │  ← FastAPI/Flask               │
│              │  (你的服务器)   │     接收→标准化→转发            │
│              └───────┬────────┘                                 │
└──────────────────────┼──────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│                        分析层                                    │
│  ┌──────────────────────────────────────────────────────┐       │
│  │  混合规则引擎：                                        │       │
│  │  1. 固定规则判断 (关键词/阈值) → 是/否                 │       │
│  │  2. LLM 分析 (上下文理解/意图识别) → 结论              │       │
│  │  3. 混合决策 (规则+LLM) → 告警等级+内容               │       │
│  └──────────────────────────────────────────────────────┘       │
└──────────────────────────┬──────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│                        输出层                                    │
│  ┌────────────────┐  ┌────────────────┐  ┌────────────────┐    │
│  │  飞书卡片推送   │  │  企业微信推送   │  │  邮件/短信     │    │
│  │  (结构化告警)   │  │  (模板卡片)    │  │  (正式通知)    │    │
│  └────────────────┘  └────────────────┘  └────────────────┘    │
└─────────────────────────────────────────────────────────────────┘
```

## 技术栈选型

| 层级 | 推荐方案 | 备选方案 |
|------|----------|----------|
| **信息接收** | 飞书 Webhook + 企业微信 API | 邮件 IMAP、网页表单、Slack Webhook |
| **统一接入** | FastAPI（异步、高性能） | Flask（简单快速） |
| **分析引擎** | Dify 工作流（可视化编排） | LangGraph（代码控制）、CrewAI（多Agent） |
| **告警推送** | 飞书卡片（结构化、可交互） | 企业微信模板卡片、邮件、短信 |
| **文档填写** | Dify + 飞书文档 API | Python-docx、Google Docs API |
| **表格填写** | Dify + 飞书多维表格 API | Python-openpyxl、Google Sheets API |

## 混合规则设计模式

### 固定规则（优先级最高）
```
关键词匹配：
- "紧急"/"故障"/"报警"/"宕机" → high
- "CPU>90%"/"内存>95%" → high
- "安全"/"入侵"/"泄露" → high

阈值匹配：
- 错误率 > 5% → medium
- 响应时间 > 2s → low
```

### LLM 分析（规则未命中时）
```
Prompt 模板：
"""
分析以下消息的告警等级：
消息：{{query}}

输出JSON（严格格式）：
{
  "alert_level": "high|medium|low|normal",
  "summary": "简短摘要（20字内）",
  "conclusion": "AI分析结论和建议",
  "keywords": ["关键词1", "关键词2"],
  "suggested_action": "建议操作"
}
"""
```

### 混合决策逻辑
```
IF rule_alert == true → 直接 high（跳过 LLM，快速响应）
ELSE → 使用 LLM 输出
```

## 避坑清单

| 坑 | 现象 | 解决方案 |
|----|------|----------|
| 飞书签名验证失败 | 403错误 | 必须实现 gen_sign 函数，时间戳用当前时间 |
| 企业微信IP不可达 | 消息收不到 | 服务器公网IP必须添加到"可信IP" |
| Dify 工作流超时 | 分析慢/失败 | 设置 response_mode: blocking，超时60s+ |
| 告警风暴 | 频繁告警轰炸 | 添加去重逻辑：5分钟内相同内容只发一次 |
| LLM误判 | 普通消息被标为告警 | Prompt中明确"正常消息不要告警"，加few-shot示例 |
| 混合规则冲突 | 规则+LLM结果不一致 | 规则优先级高于LLM，LLM只做补充判断 |
| 上下文污染 | 多Agent互相干扰 | 每个Agent独立上下文，使用 Worktree 隔离 |

## 开发节奏建议

| 阶段 | 时间 | 交付物 |
|------|------|--------|
| **MVP** | 3天 | 单通道（飞书）+ 固定规则 + 飞书告警 |
| **V1** | 1周 | 双通道（飞书+企微）+ 混合规则 + 飞书卡片 |
| **V2** | 2周 | 告警去重 + 告警历史 + 人工确认环节 |
| **V3** | 1月 | 权限系统 + 多团队支持 + 告警统计看板 |
| **V4** | 2月 | 自动填写文档 + 自动填表 + 知识库关联 |
