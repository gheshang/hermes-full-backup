# Dify 工作流：知识库问答 + 问题分类路由

> 适用场景：基于单一知识库（法规/规章/制度）的智能问答，需按问题类型调优检索策略。

## 架构概览

```
用户输入
  → [LLM 问题分类器] 判断问题类型
    ├── "条文查询" → [知识库检索] topK=3, 阈值=0.6（高精度）
    ├── "业务办理" → [知识库检索] topK=5, 阈值=0.4（高召回）
    ├── "违约处罚" → [知识库检索] topK=4, 全文搜索
    ├── "模糊问题" → [LLM 追问] 补问后再分流
    └── "报告生成" → [LLM 报告生成] 基于对话历史
  → [LLM 答案生成] 注入检索结果+原文引用
  → [变量赋值] 追加对话历史
  → 输出
```

## 节点配置

### 1. LLM 问题分类器

```
节点类型: LLM
模型: DeepSeek-V3 / Qwen2.5-72B（中文理解好，成本低）
记忆: 关闭（分类不需要历史）

系统提示词:
你是一个供电营业规则咨询助手的问题分类器。
根据用户的问题，判断属于以下哪种类型，只输出一个词：

- 条文查询：用户询问某条具体条文或规定的内容（"第几条说了什么"、"XX情况怎么规定的"）
- 业务办理：用户咨询如何办理某项业务（"怎么申请减容"、"需要什么材料"）
- 违约处罚：用户咨询违约或窃电的处罚标准（"窃电罚多少"、"违约金怎么算"）
- 模糊问题：用户的问题太过宽泛或信息不足（"帮我看看电力"、"说一下规则"）
- 报告生成：用户要求生成咨询报告或总结（"总结一下"、"出个报告"）

输出格式（严格JSON）:
{"type": "条文查询", "reason": "用户询问的是供电方式中关于频率的规定"}
```

### 2. 条件分支

```
分支1: {{分类器.text}} == "条文查询"
分支2: {{分类器.text}} == "业务办理"
分支3: {{分类器.text}} == "违约处罚"
分支4: {{分类器.text}} == "模糊问题"
分支5: {{分类器.text}} == "报告生成"
默认: 走模糊问题
```

### 3. 知识库检索（各分支不同参数）

**条文查询：**
```
检索策略: 混合检索（全文+向量）
召回数量(topK): 3
分数阈值: 0.6（高阈值，只取最相关的）
```

**业务办理：**
```
检索策略: 向量检索
召回数量(topK): 5
分数阈值: 0.4（低阈值，多召回）
```

**违约处罚：**
```
检索策略: 全文搜索（条文编号搜索效果好）
召回数量(topK): 4
分数阈值: 0.5
```

**模糊问题：** 不检索，先追问：

```
LLM 追问提示词：
用户的问题比较模糊，请向用户追问以下信息中的一项或几项（一次只问一个）：
1. 您想咨询的是哪个方面的规定？
2. 您是想办理用电业务，还是查询具体规定？
3. 能否提供更多细节，比如涉及的条款或业务名称？
```

### 4. LLM 答案生成（所有分支通用模板）

```
系统提示词：
你是一个供电营业规则咨询专家。基于知识库检索结果回答用户的问题。

回答格式要求：
1. 首先给出简明扼要的直接答案
2. 引用原文时标注条款编号（用 > 引用格式）
3. 用通俗语言解释专业术语
4. 必要时列出相关条款的编号
5. 结尾提示："以上信息仅供参考，具体以供电企业正式答复为准。"

重要规则：
- 检索结果不足时，明确说"根据已掌握的资料，无法完全回答该问题"
- 不要编造不存在的条款
- 涉及多个条款时按逻辑顺序组织

上下文：
{{知识库检索节点.result}}

用户问题：
{{用户输入}}
```

### 5. 变量赋值（记录对话历史）

```
变量名: conversation_history
赋值方式: {{conversation_history}} + "\n用户: {{用户输入}}\n助手: {{LLM答案的输出}}"
初始值: ""
```

### 6. 报告生成 LLM（当分类=报告生成时触发）

```
系统提示词：
根据此前的对话历史，生成一份"供电营业规则咨询报告"。

报告格式：
# 供电营业规则咨询报告

## 咨询概况
- 咨询时间：XXXX年XX月XX日
- 咨询主题：[自动总结]

## 咨询问题与解答
按对话顺序列出每个问题和对应的解答要点

## 涉及的主要条款
列出所有被引用的条款编号和简要内容

## 建议
- 后续需关注的条款
- 建议进一步咨询的事项
```

## 评分策略

| 评分项 | 得分点 |
|--------|--------|
| 知识库使用 | 混合检索策略 + 分类型参数调优 + 原文引用 |
| 流程编排 | 分类器 → 条件分支 → 多策略检索 → 结构化输出 |
| 流程灵活 | 模糊问题补问机制 + 报告生成可选路径 |
| Dify 原生 | 仅 LLM/知识库/条件分支/变量赋值，无外部代码 |

## 知识库分段建议

| 文档类型 | 分段标识 | 分段长度 | 重叠 |
|---------|---------|---------|------|
| 法规规章（条文式） | `## 第` 或 `第XXX条` | 2000 | 200 |
| 普通文档 | 自动分段 | 1000 | 100 |
