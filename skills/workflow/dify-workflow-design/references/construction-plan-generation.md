# Dify 工作流：施工方案报告自动生成设计模式

> 基于电力配电行业施工方案生成场景，涵盖 Markdown→docx 转换、模板+知识库+LLM 混合填充、章节规范控制。

## 应用场景

输入现场勘察单（文本/图片/表格），结合施工方案模板和处置方案知识库，自动生成符合行业规范的施工方案报告（.docx）。

## 总体架构

```
勘察单（文本/图片/表格）
  → [多模态LLM节点] 图片→结构化文本（Phase 2 扩展）
  → [知识库检索节点] 匹配模板 + 处置方案
  → [LLM节点] 按模板生成结构化 Markdown
  → [Code节点] pandoc / python-docx 转换为 .docx
  → [End节点] 返回文件
```

## 关键技术决策

### 文档生成方案：Markdown → pandoc → docx

**推荐理由：** AI 需要自由决定章节数量、表格行列、列表嵌套，占位符固定模板不够灵活。

| 方案 | 灵活性 | 格式控制 | 适用场景 |
|------|--------|----------|----------|
| docxtpl（占位符） | ❌ 固定 | ✅ 精确 | 固定表单、合同模板 |
| **pandoc + reference-docx** | ✅ 自由 | ✅ 模板控制格式 | **施工方案、技术报告（推荐）** |
| python-docx 手搓 | ✅ 自由 | ❌ 部分不支持 | 简单文档 |

### pandoc 工作流

```python
# 1. LLM 生成结构化的 Markdown 文档
# 2. 用预先调好格式的 .docx 做样式模板
# 3. pandoc 转换
import subprocess
subprocess.run([
    "pandoc", "施工方案.md",
    "--reference-doc=施工方案格式模板.docx",
    "-o", "施工方案_输出.docx"
])
```

**reference-docx 准备：** 用 Word 打开一份历史合格方案，清空内容但保留样式定义（标题1/标题2/正文/表格），另存为 `施工方案格式模板.docx`。此后所有输出都按此样式渲染。

### 模板占位符 + AI 自由生成混合

```
LLM 输出 Markdown 时遵循以下约定：
1. 标准章节名称固定（一、编制依据 / 二、工程概况 等）
2. 子章节数量由 AI 根据内容决定（### 2.1 / 2.2 / 2.3 ...）
3. 表格、列表自由生成
4. 引用标准规范时标注编号（如 GB 50194-2014）
5. 可选章节按需包含（如"绿色施工与环境保护"）
```

## 施工方案标准章节结构（GB/T 50502-2009 扩展）

基于南网 16 份真实施工方案分析得出的 **10 章节结构**：

| 章 | 名称 | 内容 | 必选 |
|----|------|------|------|
| 一 | 编制依据 | 法律法规、行业标准、设计文件、合同约定 | ✅ |
| 二 | 工程概况 | 工程简介、规模、地质地貌、参建单位 | ✅ |
| 三 | 施工组织机构及职责 | 组织架构、管理人员职责、质量安全配置 | ✅ |
| 四 | 施工安排与进度计划 | 总体部署、施工顺序、进度计划、里程碑 | ✅ |
| 五 | 施工准备 | 技术、材料、机械、劳动力、现场 | ✅ |
| 六 | 施工方法及工艺要求 | 工艺流程、主要方法、分项技术、验收标准 | ✅ |
| 七 | 质量管理与控制措施 | 质量体系、保证措施、检验标准、关键工序 | ✅ |
| 八 | 安全文明施工管理 | 安全管理、危险源、风险评价、环保 | ✅ |
| 九 | 应急预案与处置措施 | 应急组织、响应程序、处置措施、物资 | ✅ |
| 十 | 绿色施工与环境保护 | 节地/节水/节材、环保减排 | ⭐ 可选 |

**章节命名规范：**

```markdown
✅ 正确：
## 一、编制依据
### 1.1 法律法规
### 1.2 行业标准

❌ 错误：
## 第一章 编制依据（不要"第X章"）
## 1. 编制依据（一级标题用中文数字）
### 2.1、工程简介（编号后不要顿号）
```

## 处置方案知识库建设

### 需要准备的文档

按施工场景分类的组织方式：

```
处置方案库/
├── 配电室设备更换施工方案.md
├── 电缆沟开挖及敷设施工方案.md
├── 杆上变压器安装施工方案.md
├── 10kV 线路架设施工方案.md
├── 低压柜更换施工方案.md
├── 箱式变压器安装施工方案.md
└── ...
```

每个文档包含：施工流程、技术要求、安全措施、质量验收标准。

### 检索策略

```
LLM 先做场景分类（电缆/设备/杆塔/配电室...）
  → 按分类检索对应的处置方案
  → 将检索结果注入生成 Prompt
```

## Phase 分步实施

### Phase 1：文本版 MVP（~3.5h）

```
输入：勘察文本描述
  → [LLM节点] 提取关键字段（工程名称、地点、设备型号）
  → [知识库节点] 检索匹配模板 + 处置方案
  → [LLM节点] 按模板填充生成 Markdown
  → [Code节点] pandoc → .docx
  → [End节点] 返回文件
```

### Phase 2：多模态输入

```
输入：勘察照片 + 手写备注
  → [多模态LLM节点] Qwen2.5-VL 识别 → 结构化文本
  → Phase 1 流程
```

### Phase 3：飞书/企微接入

```
用户在聊天工具发文件
  → Hermes Agent 调用 Dify API
  → Dify 工作流执行
  → 返回 .docx → 飞书发送文件
```

## 风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| .docx 在 Dify Code 节点超时 | 中 | 分两段：LLM 出结构化内容，Code 只做格式转换 |
| LLM 表格不规范 | 中 | 固定表格模板，LLM 只填数据 |
| 模板匹配不准 | 低 | LLM 先做场景分类再检索 |
| 勘察照片识别错误 | 中 | 置信度 < 0.7 的字段标记"需人工复核" |
| Dify 未预装 pandoc | 低 | Code 节点 `apt-get install pandoc` 或 python-docx 替代 |
