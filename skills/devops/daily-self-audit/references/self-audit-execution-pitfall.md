# 自审结果执行陷阱

## 核心原则

**自审报告只点名 N 条，就是硬边界。超出边界 = 越权。**

## 事故复盘（2026-05-15）

### 事故经过

1. 自审 cron 输出报告指出：
   - MEMORY.md 第一条过长（375 字符），建议精简至约 200 字符
   - OpenCode CLI 条目在 MEMORY.md 和 USER.md 间重复，建议删除 MEMORY.md 版本
   - **USER.md 没有条目超过 300 字符阈值，不应被精简**

2. 代理未完整读取自审结果，擅自执行：
   - ✅ 正确：精简了 MEMORY.md 第一条
   - ❌ 越权：精简了 USER.md 的 4 条条目（自审未点名）
   - ❌ 越权：删除 OpenCode CLI 后，恢复 USER.md 时又把它写回 MEMORY.md

3. 用户指出错误后，代理恢复 USER.md 原样，仅保留 MEMORY.md 的精简。

### 教训

| 错误 | 原因 | 修正 |
|------|------|------|
| 未读完整自审结果就动手 | 凭印象/部分信息行动 | **必须先完整读取自审报告，逐项核对** |
| 精简 USER.md 未点名条目 | 认为"既然要精简就一起做了" | **自审报告是硬边界，未提及的条目不得修改** |
| 恢复时把已删除条目写回 | 恢复流程不严谨 | **恢复需对照自审原始报告逐项确认** |

## 执行规则

1. **读完整报告**：自审输出的每一条建议都要逐项核对，不能凭记忆或部分印象
2. **边界即边界**：自审报告只点名 N 条，就是硬边界。超出 = 越权
3. **宁可保守**：不确定时不动，宁可占位不误删
4. **恢复需验证**：恢复误改条目时，需对照自审原始报告逐项确认，不能凭印象

## 批量操作禁令

- `memory action=remove/replace` 用 `old_text` 子串匹配，短文本可能误伤含相同子串的其他条目
- **批量操作禁止用 memory 工具**，改用 `write_file` 直接覆盖 `~/.hermes/memories/MEMORY.md` 全量写入
- 压缩前先 `cp` 备份
